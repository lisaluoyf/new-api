# 用户模型专属折扣（第一阶段）

管理员在用户编辑页按精确模型名配置 `model_discount_ratios`。范围为
`0.000001 <= ratio <= 1`；未配置、删除规则或设置为 `1` 均不额外打折。
第一阶段只支持手动配置，不实现累计消费自动升级。
未配置当前模型的规则、空规则或倍率为 `1` 时，保留原有扣费、记账和退款流程。
异步任务只有冻结了实际生效的专属折扣时才使用新增倍率快照结算，
其余任务仍按原规则读取结算倍率。

## 扣费口径

现有采购价格、渠道用户价格、模型加价倍率和用户组倍率均不修改。
钱包最终价格 = 现有钱包价格 × 用户模型专属倍率。
例如某路线现价为官方价九五折，希望该用户变成九折，则填写
`0.9 / 0.95 = 0.947368421…`，而不是填写 `0.9`。
此倍率对同一模型的全部钱包路线生效，不保证不同基础折扣的路线都达到同一官方折扣。

专属倍率进入请求价格快照，只应用一次：预扣、重试补预扣和最终结算统一使用折后额度。
失败退款直接退还实际已扣额度，不能再次乘倍率。
实际应用专属折扣的实时语音请求，其逐段用量进入同一计费会话的累计预留额度，结束时只结算差额，
避免逐段扣费之后再按整段用量重复扣费；失败回滚也包含这些预留额度。
未应用专属折扣的实时语音请求保留原路径，本功能不包含对所有用户的语音计费改造。
标准订阅、GPT 体验额度、推荐奖励、GPT 订阅、Coding Plan 不使用该专属倍率。
采购成本和代理商成本保持原来的规则。

## 日志和记账

请求日志的原有价格与组倍率展示不变，仅在实际生效时增加
`user_model_discount`；金额仍以最终结算额度为准。
美元收入直接取最终额度除以 `QuotaPerUnit`，避免二次打折和舍入差异。
异步任务冻结折后组倍率和专属倍率，完成时不重新读取管理员当前配置。
异步补退差额同步原消费日志的最终收入，采购成本独立更新；失败时冲销收入。

模型页的公共响应和价格不变，登录用户通过私有、不缓存的接口读取自己的规则，
单独显示“用户专属折扣”；未配置或免费模型不展示额外折扣。
